# v1.1 Multi-Adapter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add 13 new batch-only data source adapters to reach ccusage feature parity, while leaving daemon / SQLite / Claude / Codex paths completely untouched.

**Architecture:** Each new source gets a `collector.Load<Name>Entries(ctx, opts)` function (plain Go, no trait/interface abstraction — flat like ccusage). A new `cmd/tm/cli/adapters.go` wraps these collector functions into `AggregateLoader` for the existing `RunAggregate` pipeline. `RunAggregate` learns an all-source merge path that walks the SQLite store + every registered batch adapter; `--no-scan` falls back to v1.0 SQLite-only behavior.

**Tech Stack:** Go 1.24 · `encoding/json` for JSON/JSONL adapters · `modernc.org/sqlite` (already in deps) for SQLite-backed adapters (Goose / Hermes / Kilo) · `os.ReadDir` + `path/filepath.Glob` for log discovery · fixture-driven testing borrowing from ccusage MIT-licensed test data.

**Spec reference:** `docs/superpowers/specs/2026-05-21-v1.1-multi-adapter-design.md` (commit `759ca34`). Decisions V1–V6 are binding.

**ccusage source reference:** `/Users/admin/code/ccusage/rust/crates/ccusage/src/adapter/<name>.rs` — read this file before implementing each adapter; the Rust parsing logic is the ground truth for log shape, edge cases, and pricing field extraction.

```go
// Package cli — adapters.go wires batch-only collector functions into the
// same AggregateLoader interface the SQLite path uses.
package cli

import (
	"context"
	"time"

	"github.com/tt-a1i/tokenmeter/internal/collector"
	"github.com/tt-a1i/tokenmeter/internal/storage"
)

// AdapterLoadFn matches the standard collector.Load<Name>Entries signature.
type AdapterLoadFn func(ctx context.Context, opts collector.AdapterOpts) ([]collector.UsageEntry, error)

// AdapterLoaderFromFn adapts an in-memory batch collector to the
// AggregateLoader interface that RunAggregate / RunSession expect.
func AdapterLoaderFromFn(fn AdapterLoadFn) AggregateLoader {
	return &adapterLoader{fn: fn}
}

type adapterLoader struct {
	fn AdapterLoadFn
}

func (a *adapterLoader) ListUsageForBlocksFiltered(ctx context.Context, since, until time.Time, project string) ([]storage.TokenUsageEntry, error) {
	opts := collector.AdapterOpts{Since: since, Until: until, Project: project}
	entries, err := a.fn(ctx, opts)
	if err != nil {
		return nil, err
	}
	out := make([]storage.TokenUsageEntry, len(entries))
	for i, e := range entries {
		out[i] = storage.TokenUsageEntry{
			SourceID:                 e.SessionID, // best-effort unique id; storage layer doesn't insert these
			SessionID:                e.SessionID,
			Timestamp:                e.Timestamp,
			Model:                    e.Model,
			InputTokens:              e.InputTokens,
			OutputTokens:             e.OutputTokens,
			CacheCreationInputTokens: e.CacheCreationInputTokens,
			CacheReadInputTokens:     e.CacheReadInputTokens,
			CostUSD:                  e.CostUSD,
		}
	}
	return out, nil
}
```

> **Project filter caveat:** most adapters ignore `Project` (their log paths don't carry workspace info the same way Claude sessions do). The loader passes it through; per-adapter behavior is documented in each Task body.

In `cmd/tm/cli/aggregate.go`:

```go
// RunAggregateAllSource is the all-source variant invoked when `tm daily`
// (no specific source) runs without --no-scan. It loads SQLite entries
// plus every registered batch adapter, then re-uses the existing groupBy
// + table renderer.
func RunAggregateAllSource(ctx context.Context, w io.Writer, a AggregateArgs, sqliteLoader AggregateLoader, adapters map[string]AdapterLoadFn) error {
	since := parseDateOrZero(a.Shared.Since)
	until := parseDateOrZero(a.Shared.Until)
	all, err := sqliteLoader.ListUsageForBlocksFiltered(ctx, since, until, a.Shared.Project)
	if err != nil {
		return err
	}
	for source, fn := range adapters {
		entries, err := fn(ctx, collector.AdapterOpts{Since: since, Until: until, Project: a.Shared.Project})
		if errors.Is(err, fs.ErrNotExist) {
			continue // user does not have this agent installed
		}
		if err != nil {
			fmt.Fprintf(os.Stderr, "warning: %s adapter failed: %v\n", source, err)
			continue
		}
		for _, e := range entries {
			all = append(all, storage.TokenUsageEntry{
				SourceID: e.SessionID, SessionID: e.SessionID, Timestamp: e.Timestamp,
				Model: e.Model, InputTokens: e.InputTokens, OutputTokens: e.OutputTokens,
				CacheCreationInputTokens: e.CacheCreationInputTokens,
				CacheReadInputTokens:     e.CacheReadInputTokens,
				CostUSD:                  e.CostUSD,
			})
		}
	}
	return renderAggregate(w, all, a)
}

// renderAggregate factors out the existing render logic from RunAggregate.
// If RunAggregate is currently monolithic, refactor it to call renderAggregate
// for the SQLite-only path so both paths share output formatting.
func renderAggregate(w io.Writer, entries []storage.TokenUsageEntry, a AggregateArgs) error {
	groups := groupBy(entries, a.Bucket)
	keys := make([]string, 0, len(groups))
	for k := range groups {
		keys = append(keys, k)
	}
	sort.Strings(keys)
	tw := tabwriter.NewWriter(w, 0, 0, 2, ' ', 0)
	fmt.Fprintln(tw, "DATE\tMODELS\tTOKENS\tCOST")
	for _, k := range keys {
		g := groups[k]
		fmt.Fprintf(tw, "%s\t%s\t%s\t$%.2f\n", k, joinModels(g.models), fmtInt(g.tokens), g.cost)
	}
	return tw.Flush()
}

func parseDateOrZero(s string) time.Time {
	if s == "" {
		return time.Time{}
	}
	t, err := time.Parse("20060102", s)
	if err != nil {
		return time.Time{}
	}
	return t
}
```

# Migrating to TokenMeter v1.1

## TL;DR

v1.1 ships 13 new data source adapters. The only behavior change for existing
users is **`tm daily` (no source) now scans batch adapters by default**. If
your scripts depend on `tm daily` returning only Claude + Codex data, add
`--no-scan` to restore v1.0.x behavior.

## New subcommands

Each of these 13 sources now has full `daily / weekly / monthly / session`
bucket support, identical to `tm claude daily` and `tm codex daily`:

| Source | Subcommand prefix | Log location | Env override |
|---|---|---|---|
| OpenCode | `tm opencode` | `~/.local/share/opencode/` | `OPENCODE_DATA_DIR` |
| Amp | `tm amp` | `~/.local/share/amp/threads/*.json` | `AMP_DATA_DIR` |
| Gemini CLI | `tm gemini` | `~/.gemini/tmp/chats/*` | `GEMINI_DATA_DIR` |
| Copilot CLI | `tm copilot` | `~/.copilot/otel/*.jsonl` | `COPILOT_OTEL_FILE_EXPORTER_PATH` |
| Goose (SQLite) | `tm goose` | `~/.local/share/goose/sessions/<db>` | `GOOSE_PATH_ROOT` |
| Codebuff | `tm codebuff` | `~/.config/<channel>/projects/...` | `CODEBUFF_DATA_DIR` |
| Hermes (SQLite) | `tm hermes` | `~/.hermes/state.db` | `HERMES_HOME` |
| Kilo (SQLite) | `tm kilo` | `~/.local/share/kilo/<db>` | `KILO_DATA_DIR` |
| Kimi | `tm kimi` | `~/.kimi/sessions/...` | `KIMI_DATA_DIR` |
| OpenClaw | `tm openclaw` | `~/.openclaw/`, `~/.clawdbot/`, etc. | `OPENCLAW_DIR` |
| pi-agent | `tm pi` | `~/.pi/agent/sessions/...` | `PI_AGENT_DIR` |
| Droid | `tm droid` | `~/.factory/sessions/*.settings.json` | `DROID_SESSIONS_DIR` |
| Qwen | `tm qwen` | `~/.qwen/projects/<project>/chats/*.jsonl` | `QWEN_DATA_DIR` |

## `tm daily` behavior change

**v1.0.x**: `tm daily` queries only SQLite (Claude + Codex).
**v1.1.0**: `tm daily` queries SQLite *and* scans every batch adapter listed
above. Adapters whose log directory does not exist are silently skipped
(`< 5 ms` overhead per missing source).

If you have a script that expects only Claude + Codex rows, use one of:
- `tm daily --no-scan` — explicitly skip batch adapters
- `tm claude daily` and `tm codex daily` — query each source individually

## Data is not migrated into SQLite

Batch adapter data is *not* written into TokenMeter's SQLite store. Each
`tm <source> daily` invocation re-scans the source's logs. This matches
ccusage's stateless model. The daemon, SQLite schema, and Claude / Codex
collection paths are unchanged from v1.0.x.

## Project filter (`--project`)

`--project <path>` works for Claude / Codex (matches `sessions.cwd`). Most
batch adapters cannot map workspace paths reliably from their logs and
silently ignore `--project`. Adapter-by-adapter support is documented in the
table above (if unspecified, `--project` is ignored).
