# v1.0.1 — ccusage 对齐 (Part 1)

**作者**: tt-a1i 团队（star + cloud + reviewer）
**日期**: 2026-05-20
**状态**: 已批准

## 背景

v1.0.0 已对齐 ccusage 的命令面（`daily/weekly/monthly/session/blocks/statusline`），但发现两类问题：

1. **flag 已在 `cli.go` 注册但 `RunXxx` 路径没接通**：`--json` / `--breakdown` / `--order` / `--mode` / `--project` / `--timezone` / `--no-color` / `--jq` 全部不生效。
2. **输出格式与 ccusage 视觉差距大**：tm 是 `DATE | MODELS | TOKENS | COST` 四列、无颜色、无 totals 行；ccusage 是 8 列圆角边框 + 彩色 + TOTAL 汇总。

性能方面，`tm daily` 在 1587 sessions / 575MB DB 上耗时 800ms。需要先 profile 找热点再决定是否优化。

v1.0.1 是 ccusage 对齐工作的 **Part 1**：补齐 ship-blocker、做输出视觉对齐、建立性能基线。

## 非目标（留给 v1.0.2/v1.1）

- 短 flag 别名（`-j -s -u -z -O -m -d -o -b`）
- `--instances` / `--project-aliases` / `--start-of-week` / `--recent` / `--token-limit`
- statusline 高级 flag（`--cache` / `--refresh-interval` / `--visual-burn-rate` / `--cost-source` / `--context-*-threshold`）
- `--compact` 窄终端模式
- `-d/--debug` + `--debug-samples` pricing 诊断
- `--config <path>` 自定义路径
- 多 adapter（OpenCode / Amp / Gemini / Copilot / Goose）
- Web Dashboard 升级
- 性能优化承诺（v1.0.1 只 measure，不 commit target）

## Phase A — flag 接通

ship-blocker 性质，全部影响 v1.0.0 用户体验。

### A1. `cli/aggregate.go::RunAggregate`
当前：忽略 `Shared.JSON/Order/Breakdown/Mode/Project/Timezone`。
目标：
- 读 `Shared.JSON`，分支到 JSON renderer 或 table renderer
- 读 `Shared.Order`（`asc` / `desc`），影响 result slice 排序
- 读 `Shared.Mode`（`auto` / `calculate` / `display`），传给 `pricing.Apply`
- 读 `Shared.Project`，传给 `ListUsageForAggregateFiltered`（如已存在）或新增 filtered 路径
- 读 `Shared.Timezone`，用 IANA TZ 加载 `*time.Location`，传给 `bucketKey`
- 读 `Shared.Breakdown`，决定渲染时是否展开 model-level 行

### A2. `cli/session.go::RunSession`
同 A1，针对 session 路径。

### A3. `cli/blocks.go::RunBlocks`
接通 `--json`、`--mode`、`--project`、`--timezone`。
`--token-limit` 与 `--recent` 留 v1.0.2。

### A4. `cli/statusline.go::RunStatusline`
接通 `--mode`、`--no-color`、`--project`。
`--cache` 等留 v1.0.2。

### A5. `cli/router.go`
当前：`tm`（无参）打印 help。
目标：`tm`（无参）默认执行 `daily`，与 ccusage 行为对齐。`tm help` 仍打印 help。

## Phase B — 输出对齐 ccusage

### B1. 引入 `internal/render/`
新包，封装表格 / JSON 渲染。

```go
package render

type Table interface {
    Render(io.Writer) error
}

type AggregateRow struct {
    Bucket          string    // "2026-05-19" / "2026-W21" / "2026-05"
    Project         string    // 可选
    Models          []string
    InputTokens     int64
    OutputTokens    int64
    CacheCreateTokens int64
    CacheReadTokens int64
    TotalTokens     int64
    Cost            float64
    Breakdown       []ModelBreakdown // --breakdown 时填
}

type ModelBreakdown struct {
    Model           string
    InputTokens     int64
    OutputTokens    int64
    CacheCreateTokens int64
    CacheReadTokens int64
    TotalTokens     int64
    Cost            float64
}

func NewBoxedTable(rows []AggregateRow, opts Options) Table
func NewJSONOutput(rows []AggregateRow, kind string) Table  // kind="daily"/"weekly"/"monthly"/"session"

type Options struct {
    Color     bool   // false 时全部黑白
    Breakdown bool
}
```

### B2. 表格库
依赖 `github.com/jedib0t/go-pretty/v6/table`。
- 圆角边框：`table.StyleRounded`
- ANSI 颜色：`text.Colors{text.FgRed}`（COST 红）/ `text.FgYellow`（TOKENS 黄）/ `text.FgCyan`（Models 青）
- 列宽自适应

不再自己手写 padding。

### B3. 列对齐 ccusage
```
DATE | MODELS | INPUT | OUTPUT | CACHE CREATE | CACHE READ | TOTAL | COST
```
末行 TOTAL 汇总（每列求和，MODELS 列空白）。

Session 命令第一列改为 `SESSION`，并加 `PROJECT` 列。

### B4. JSON schema 对齐 ccusage
camelCase 字段、顶层结构：

```json
{
  "daily": [
    {
      "date": "2026-05-19",
      "modelsUsed": ["claude-opus-4-7"],
      "inputTokens": 1200,
      "outputTokens": 45000,
      "cacheCreationTokens": 8000,
      "cacheReadTokens": 420000,
      "totalTokens": 474200,
      "totalCost": 18.83,
      "modelBreakdowns": [
        {
          "model": "claude-opus-4-7",
          "inputTokens": 1200,
          "outputTokens": 45000,
          "cacheCreationTokens": 8000,
          "cacheReadTokens": 420000,
          "totalTokens": 474200,
          "totalCost": 18.83
        }
      ]
    }
  ],
  "totals": {
    "inputTokens": 4600,
    "outputTokens": 134000,
    "cacheCreationTokens": 20000,
    "cacheReadTokens": 932000,
    "totalTokens": 1090600,
    "totalCost": 61.01
  }
}
```

- `daily` / `weekly` / `monthly` 顶层 key 对应命令
- `session` 顶层为 `sessions: [...]`，每项含 `sessionId` / `projectPath` / `lastActivity`
- `blocks` 顶层为 `blocks: [...]`，每项含 block 字段（startTime / endTime / isActive / projection / burnRate）

### B5. `--breakdown` 行内嵌套
开启时，每个 bucket 行下面加一条或多条 model-level 子行，第一列变成 `└─ <model>` 缩进展示。

### B6. 颜色检测
- 检测 stdout `isatty`（用 `golang.org/x/term::IsTerminal` 或 `github.com/mattn/go-isatty`）
- 检测 `NO_COLOR` / `FORCE_COLOR` 环境变量
- `--no-color` 强制关闭
- `--json` 模式强制关闭颜色（避免污染管道）
- 默认：tty 上彩色，pipe / file 重定向时无色

## Phase C — 闭区间 + 边界

### C1. `--until` 改闭区间
当前 ccusage 文档说 `--until YYYYMMDD inclusive`。tm 当前是 `< until 开始` 半开区间。
修：在 `parseDateFlag` 解析 `Until` 之后 +24h（变 `< until 次日 00:00`），等效闭区间。

### C2. 空范围提示
当 query 返回 0 行时，输出 `(no data in range)` 而不是空表头。

## Phase D — 性能 profile

### D1. `--cpu-profile <path>` hidden flag
所有 subcommand 共享（`cli/cli.go` ParseShared 注册）。
`runtime/pprof::StartCPUProfile`。

### D2. 基线 measurement
执行：
```bash
./tm daily --cpu-profile /tmp/daily.pprof > /dev/null
go tool pprof -top -cum /tmp/daily.pprof
```
报告 top 10 函数（accum CPU%）写进 `docs/perf/v1.0.1-baseline.md`。

### D3. 范围之外
v1.0.1 不承诺优化 target。基于报告决定 v1.0.2 优化方向：
- 如果 SQLite open 占大头 → 索引 / WAL checkpoint
- 如果 pricing unmarshal 占大头 → sync.Once + cache
- 如果 daemon socket dial 占大头 → 取消（CLI 直读 SQLite，不需要 dial daemon）

## 接口契约

### `internal/storage::ListUsageForAggregate`
当前签名：
```go
func (s *DB) ListUsageForAggregate(since, until time.Time) (...)
```
扩展到（保持向后兼容，新增 `Filtered` 后缀方法）：
```go
type AggregateFilter struct {
    Since   time.Time
    Until   time.Time
    Project string  // 空 = 不过滤；非空 = 按 sessions.cwd 过滤
}

func (s *DB) ListUsageForAggregateFiltered(f AggregateFilter) ([]UsageRow, error)
```

`UsageRow` 必含 `InputTokens / OutputTokens / CacheCreationTokens / CacheReadTokens / Model / Cost / Timestamp / Project`。

### `internal/blocks::Aggregate` 不变
v1.0 的 `blocks.Annotate(blocks.Identify(rows))` 仍为单一入口。

### `cmd/tm/cli/aggregate.go::RunAggregate` 改签名
当前：
```go
func RunAggregate(loader AggregateLoader, bucket Bucket, args AggregateArgs) error
```
扩展：
```go
type AggregateArgs struct {
    Shared        cli.Shared
    Bucket        Bucket  // Daily / Weekly / Monthly
}
```
`Shared` 中 `JSON / Order / Breakdown / Mode / Project / Timezone / NoColor` 全部使用。

## 风险

- **`go-pretty` 包体积**：+200KB binary 增长；可接受。
- **JSON schema 变化**：v1.0.0 用户如已写脚本依赖旧 JSON 输出 → 但 v1.0.0 的 `--json` 根本没工作，所以无破坏。
- **`--until` 语义变化**：v1.0.0 是半开区间，现在闭区间。MIGRATION 文档明示。
- **timezone 边界**：bucketKey 用 IANA TZ，时区切换日可能边界数据归属不同 bucket。test 覆盖跨时区案例。
