# v1.0.2 — SQL Push-Down 性能优化

**作者:** tt-a1i 团队（star + cloud + reviewer + 海盐）
**日期:** 2026-05-20
**状态:** 已批准

## 背景

v1.0.1 已 ship；`docs/perf/v1.0.1-baseline.md` 实测 `tm daily` warm 820 ms / cold 2.4 s（1587 sessions / 575 MB DB / 445k token_usage rows）。

pprof 报告确认热点：
- `syscall.Pread` via SQLite page reads — 71% flat
- `_sqlite3VdbeExec` row iteration — 72% cum
- `database/sql.Rows.Next` + `scanUsageRows` — 47.6% / 51.4% cum

`EXPLAIN QUERY PLAN` 已经走 `idx_token_usage_ts` SCAN（不是缺索引）。瓶颈是 **CLI 层拉全 445k 原始 row 回 Go 做 groupBy**。

实测 SQL 端 `GROUP BY date(timestamp)` warm = 244 ms（含 model 二级分组），比 v1.0.1 现状快 3.4×。

v1.0.2 用 SQL push-down 把 daily / weekly / monthly / session 命令的 groupBy 全部下移到 SQLite 端。

## 非目标（留给 v1.0.3 / v1.1+）

- 加 covering index（DB +30% 磁盘成本，留待用户实际反馈）
- 改 `tm blocks` 性能（5 h block 识别需要 raw timeline，本身不在热点）
- 多 adapter（OpenCode / Amp / Gemini / Copilot / Goose）
- Web Dashboard 升级
- C 类 flag（短 flag 别名 / `--instances` / `--recent` / `--token-limit` / statusline 高级 flag）
- WAL 优化 / connection pool tuning
- cold cache 优化（用户低频，warm 是高频路径）

## 性能目标（验收）

| 命令 | v1.0.1 warm | v1.0.2 目标 |
|---|---|---|
| `tm daily` | 820 ms | <250 ms |
| `tm weekly` | ~820 ms | <250 ms |
| `tm monthly` | ~820 ms | <250 ms |
| `tm session` | ~820 ms | <300 ms |
| `tm blocks` | ~820 ms | 不退步（不优化） |
| `tm statusline` | ~10 ms | 不退步 |

Baseline 在 1587 sessions / 575 MB DB / 445k rows 上测；v1.0.2 复测同一 DB。

## Phase A — storage 层 SQL push-down

### A1. `internal/storage/aggregate.go` 新建（types）

```go
package storage

import "time"

type AggregateBucket int

const (
    BucketDay AggregateBucket = iota
    BucketWeek
    BucketMonth
    BucketSession
)

type AggregateFilter struct {
    Since     time.Time
    Until     time.Time
    Project   string         // sessions.cwd 精确匹配；"" 跳过过滤
    Bucket    AggregateBucket
    Breakdown bool           // by model 加二级 GROUP BY
    Location  *time.Location // 影响 day/week/month bucket key；nil = UTC
}

type AggregateUsageRow struct {
    Bucket            string    // "2026-05-19" / "2026-W21" / "2026-05" / session_id
    Model             string    // Breakdown=false 时 ""；true 时单 model
    Models            []string  // Breakdown=false 时填 distinct models；true 时 nil
    InputTokens       int64
    OutputTokens      int64
    CacheCreateTokens int64
    CacheReadTokens   int64
    Cost              float64
    Project           string    // BucketSession 时填 sessions.cwd
    LastActivity      time.Time // BucketSession 时填 MAX(timestamp)
}

func (s *DB) AggregateUsage(ctx context.Context, f AggregateFilter) ([]AggregateUsageRow, error)
```

### A2. SQL 模板

由 `AggregateUsage` 内根据 `f.Bucket` / `f.Breakdown` / `f.Location` 拼装。**单一函数，单一接口**。

#### Day bucket

```go
tzModifier := ""
if f.Location != nil && f.Location != time.UTC {
    _, offset := time.Now().In(f.Location).Zone()
    tzModifier = fmt.Sprintf(", '%+d seconds'", offset)
}
bucketExpr := "date(u.timestamp" + tzModifier + ")"
```

```sql
SELECT
  {bucketExpr} AS bucket,
  {model_col_or_concat},
  SUM(u.input_tokens), SUM(u.output_tokens),
  SUM(u.cache_creation_tokens), SUM(u.cache_read_tokens),
  SUM(u.cost_usd)
FROM token_usage u
JOIN sessions s ON s.session_id = u.session_id
WHERE u.timestamp >= ? AND u.timestamp <= ?
  [AND s.cwd = ?]
GROUP BY 1 {, model_col}
ORDER BY 1 ASC {, model ASC}
```

- `Breakdown=false`: `model_col_or_concat = GROUP_CONCAT(DISTINCT u.model)`
- `Breakdown=true`: `model_col_or_concat = u.model`，GROUP BY 加 `, u.model`

#### Week bucket

SQLite `strftime('%Y-%W', ...)` 是 ISO Week-of-Year — 与 Go `time.ISOWeek()` 行为略不同（SQLite `%W` 周从周一开始，但 ISO 周日的标号可能差一）。

**决策**：v1.0.2 周边界与 Go `time.ISOWeek()` 对齐 → SQL 用 `strftime('%Y-W%W', u.timestamp ...)` + cli 层兜底修正。或简化版：直接用 `strftime('%Y-W%W', ...)` 输出，跟 Go 的 ISO week 差异 < 1 周边界 case，文档记 known limit。

实施时若发现差异 > 0 天，退化方案：cli 层做周分组（性能损失 < 5%，仍优于 v1.0.1）。

#### Month bucket

`strftime('%Y-%m', u.timestamp[, tzModifier])` — SQLite 与 Go 完全一致。

#### Session bucket

```sql
SELECT
  u.session_id AS bucket,
  GROUP_CONCAT(DISTINCT u.model),
  SUM(u.input_tokens), SUM(u.output_tokens),
  SUM(u.cache_creation_tokens), SUM(u.cache_read_tokens),
  SUM(u.cost_usd),
  s.cwd AS project,
  MAX(u.timestamp) AS last_activity
FROM token_usage u
JOIN sessions s ON s.session_id = u.session_id
WHERE [filters]
GROUP BY u.session_id, s.cwd
ORDER BY u.session_id
```

session 路径自带 project / last_activity 列。

### A3. 边界细节

- **timezone**：用 SQLite `date(timestamp, '+N seconds')` modifier 实现；偏移取自 `f.Location` 上当前时刻的 zone offset。已知边界：跨 DST 切换日，partial day 会归属"切换前"或"切换后" — 文档 known limit。
- **GROUP_CONCAT(DISTINCT model)** 输出顺序未定义 → cli 层接到后 `sort.Strings(row.Models)` 兜底。
- **空范围**：SQL 返 0 行；cli 层照 v1.0.1 行为输出 `(no data in range)`。
- **NULL model**：少数 Codex 行可能没 model；SQL 端用 `COALESCE(u.model, '')`，cli 层渲染时显示 `-`（同 v1.0.1 joinList）。
- **cost mode**：`Mode = calculate / display` 仍在 cli 层处理。SQL 永远返回 `SUM(cost_usd)`；cli 层在 `Mode=calculate` 时**按 SUM token counts × pricing** 重算（精度可能与逐 entry 重算略有差异 — Mode=calculate 是估算用，可接受）。`Mode=auto` 时 SQL 端 SUM(cost_usd) 直接用。

## Phase B — cli 层切换

### B1. `cli/aggregate.go::RunAggregate`

```go
func RunAggregate(ctx context.Context, w io.Writer, a AggregateArgs, loader AggregateLoader) error {
    since, _ := parseDateFlag(a.Shared.Since)
    until, _ := ParseDateFlagUntil(a.Shared.Until)
    
    loc := time.UTC
    if a.Shared.Timezone != "" {
        loc, _ = time.LoadLocation(a.Shared.Timezone)
    }
    
    filter := storage.AggregateFilter{
        Since: since, Until: until,
        Project:   a.Shared.Project,
        Bucket:    bucketFromCLI(a.Bucket),  // BucketDaily -> storage.BucketDay etc
        Breakdown: a.Shared.Breakdown,
        Location:  loc,
    }
    
    aggRows, err := loader.AggregateUsage(ctx, filter)
    if err != nil { return err }
    
    if a.Shared.Mode != "" && a.Shared.Mode != "auto" {
        aggRows = applyPricingModeToAggregate(aggRows, pricing.ParseMode(a.Shared.Mode))
    }
    
    renderRows := convertToRenderRows(aggRows, a.Shared.Breakdown)
    if a.Shared.Order == "desc" {
        reverse(renderRows)
    }
    
    return render.New().RenderAggregate(w, bucketKind(a.Bucket), renderRows, renderOpts(a.Shared, w))
}
```

- 删除 `aggGroup` 在 cli 层的 in-memory 聚合
- `applyPricingModeToAggregate` 是新 helper：对 AggregateUsageRow 做 cost 重算（基于 SUM token + model price）
- `convertToRenderRows` 把 storage rows 转 render rows（Breakdown=true 时合并同 bucket 不同 model 行）

## 风险

1. **Mode=calculate 精度漂移**：cli 层 SUM 后重算 vs 逐 entry 重算 → 小数尾差 < $0.01，可接受。MIGRATION 文档提一句。
2. **SQLite Week 行为**：`strftime('%Y-W%W', ...)` 与 Go `time.ISOWeek` 周一对齐方式可能有偏差。Phase A2 已写 fallback 方案。
3. **GROUP_CONCAT 顺序不稳**：cli 层 `sort.Strings(row.Models)` 兜底。
4. **timezone DST**：跨 DST 切换日跨 partial day。known limit 文档记。
5. **blocks `PerModel` 字段**：扩 `blocks.SessionBlock` 是 public API 变化。如果有 third-party 用 internal/blocks（不该有，但），加字段不破坏现有 struct literal — 安全。

## 工程纪律

- 包内串行，包外并发：
  - `internal/storage/aggregate.go` 由一个 worker 独占
  - `cmd/tm/cli/aggregate.go` + `session.go` 由另一个 worker
  - `internal/blocks/types.go` 改 PerModel 时由 cli/blocks 同 worker 做（隔离 commit）
  - `internal/render/boxed.go` 同 worker 改 RenderBlocks Breakdown
  - `CHANGELOG.md` / `docs/perf/` 由一个 worker
- `&&` chain atomic commit + 反向白名单 gate（v1.0.1 验过的协议，5+ task 零 race）
- commit message 无 Claude 品牌、无 Co-Authored-By
- 不 skip hooks、不 force push、不改 git config
