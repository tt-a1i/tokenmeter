## Command Notes

- The dispatch example used `tm daily --range all`, but current `tm daily --help` has no `--range` flag. Running that exact command returns `parse flags: flag provided but not defined: -range` with exit 1.
- I reran daily checks with the current valid CLI command, `tm daily`, which is the documented form in command help.
- The dispatch example suggested `touch` to age the cache file. Current implementation uses the JSON `fetchedAt` field, not file mtime, for TTL. `touch` alone does not make the cache stale. I verified TTL by setting `.fetchedAt` to 25 hours ago.

## Findings

- Live refresh is fixed end to end after 718d2e1: LiteLLM data now parses and writes the runtime cache.
- Daily uses runtime cache without pricing errors. The cache-backed daily total was `$2796.43`.
- Corrupt cache under offline mode falls back to embedded pricing and still exits 0. The embedded fallback total was `$2779.68`, which differs from the cache-backed total and confirms the runtime cache changes effective pricing.
- Stale runtime cache is served immediately and refreshed asynchronously when `.fetchedAt` exceeds the 24h TTL.
- `pricing refresh --offline` exits 1 even when cache exists. That matches current `RefreshRuntime` semantics: refresh is an explicit network action, and offline means "skip refresh", not "serve cache".

## Design Clarification

- `tm pricing refresh --offline` should remain exit 1 with `pricing refresh skipped: offline mode` unless product semantics are changed. Cache serving belongs to commands that call `LoadRuntime` (`daily`, etc.), not the explicit refresh command.
- TTL is controlled by cache metadata (`fetchedAt`), not filesystem mtime. Release/checklist docs should avoid using `touch` as a TTL simulation unless they also rewrite `fetchedAt`.

## Conclusion

Pricing closed-loop is end-to-end working:

1. live refresh writes cache,
2. daily loads cache,
3. offline refresh intentionally skips with exit 1,
4. stale cache triggers async refresh,
5. corrupt cache plus offline mode falls back to embedded pricing.

No new v1.2 blocker found.
