## C. Hacker News draft

Title:

Show HN: TokenMeter v1.2 — local usage dashboard for AI coding CLIs

Body:

Background: ccusage is a useful CLI for tracking Claude Code and Codex token usage. We've been using that model for months, then built TokenMeter as a local daemon + CLI + dashboard around the same basic need.

v1.2 closes 9 P0/P1 alignment gaps with ccusage: 15 source CLIs, LiteLLM runtime pricing sync, Codex `--speed` tier, OpenCode SQLite, Droid sidecar metadata fallback, responsive tables, project aliases, statusline thresholds, `blocks --token-limit`, and unified config.

The part I'm most interested in is what persistence enables beyond usage totals:

1. `tm analyze --tool-errors`: failure-rate ranking + error pattern clustering + daily failure trend. On our local data this surfaced a WebFetch 28.9% failure rate, a signal daily/session reports do not show.
2. `tm analyze --file-churn`: ranks files by edit frequency across sessions. Real data showed MapView.tsx with 365 changes across 8 sessions.
3. `cost_spike` + `usage_regression` webhook events with cooldown.
4. `tm search error tool:Bash cost:'>1' since:2026-05-01`: FTS5-backed search with structured filters.

Stack: Go 1.24, modernc SQLite, single binary. The daemon is optional; the per-command CLI reports still work without it.

Source: https://github.com/tt-a1i/tokenmeter
Docs: VitePress docs live in `docs/site/`; hosted deployment is pending.
