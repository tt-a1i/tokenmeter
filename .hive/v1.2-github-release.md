# TokenMeter v1.2.0

> Local usage dashboard for AI coding agents: Claude Code, Codex, OpenCode, and 12 more source CLIs.

## What's new

TokenMeter v1.2.0 turns the v1.1 multi-source reporter into a broader local observability dashboard for AI coding agents.
It closes 9 ccusage-alignment gaps across pricing, source loaders, responsive reports, statusline controls, token-limit blocks, project aliases, and unified config.
It also adds four TokenMeter-only dimensions: tool error analysis, file churn, webhook anomaly detection, and an FTS5-backed search DSL.

## 🚀 Beyond ccusage (4 new dimensions)

### Tool error pattern analysis

```bash
tm analyze --tool-errors
```

Ranks failing tools, groups repeated error patterns, and shows a daily failure-rate trend.
On a real local dataset, this surfaced a `WebFetch` 28.9% failure rate, a reliability signal that daily/session token totals do not expose.

### File churn heatmap

```bash
tm analyze --file-churn
```

Reports top changed files with mode breakdown, depth-2 directory hotspots, and daily file-change trends.
On a real local dataset, this identified `MapView.tsx` with 365 changes across 8 sessions, making review hotspots visible without reading Git history first.

### Webhook anomaly detection

```text
cost_spike + usage_regression events with cooldown
```

The daemon can emit `cost_spike` events when today's spend exceeds the recent baseline and `usage_regression` events when a tool's failure rate regresses.
Cooldowns reduce duplicate notifications during noisy periods.

### FTS5 advanced search DSL

```bash
tm search error tool:Bash cost:'>1' since:2026-05-01
```

Search now combines text with structured filters: `tool:`, `session:`, `status:`, `platform:`, `cost:`, `tokens:`, `since:`, and `until:`.
This makes local tool calls, results, and file paths searchable without leaving the terminal.

```bash

```

## 📋 Known limitations / follow-up

- `sources.<name>` config schema exists but is not yet applied to adapter-specific defaults.
- `session-length` remains a CLI flag and is not part of unified config defaults.
- Anomaly webhook cooldown is in-memory; daemon restart resets cooldown state.
- Droid sidecar JSONL model fallback scans only the first 500 lines of large logs.
- OpenCode SQLite open/query/scan errors are silently skipped for batch resilience.
