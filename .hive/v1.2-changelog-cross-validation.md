## E. Known limitations

### 公孙弘列出的 known limitations 准确性

1. `sources.<name>` schema exists but is not applied yet — **准确**。
   - Schema exists: `internal/config/config.go:21`, `internal/config/config.go:44-47`.
   - Shared parsing applies global defaults / commands, but no source namespace is consumed in `cmd/tm/cli/cli.go:46-76` or adapter route setup.

2. `session-length` is not in unified config defaults — **准确**。
   - `Defaults` has no `SessionLength` field: `internal/config/config.go:26-40`.
   - CLI parses `--session-length` only as a flag defaulting to `5h`: `cmd/tm/cli/cli.go:72-73`.

3. Anomaly webhook cooldown is in-memory — **准确**。
   - State lives in `Daemon.anomalyLastAlert map[string]time.Time`: `internal/daemon/daemon.go:40-65`.
   - Cooldown reads/writes that map only: `internal/daemon/anomaly.go:110-121`.

4. Tool error grouping depends on `result_summary` — **准确**。
   - Rendering and storage grouping use captured result summaries; old failures without summaries cannot form useful patterns. Evidence: `internal/render/tool_errors.go:23-30`; storage normalizes result summaries via `NormalizeToolErrorPattern` in `internal/storage/tool_errors.go`.

### 遗漏的 known limitations / follow-up

1. **[P2] Droid sidecar model fallback scans only first 500 lines.**
   - Evidence: `internal/collector/droid.go:296-299`.
   - Impact: model strings after line 500 are ignored. Usually acceptable, but release notes should not imply exhaustive sidecar scanning.

2. **[P2] OpenCode SQLite read errors are silent fallback/skip.**
   - Evidence: `internal/collector/opencode.go:213-222` returns nil on `sql.Open` / query errors; `LoadOpenCodeEntries` then continues to JSON fallback.
   - Impact: corrupt or schema-drifted SQLite stores can degrade silently. This matches current adapter tolerance, but is worth noting if "reads modern opencode.db" is presented as hard guarantee.

3. **[P2] File churn analysis is global over `file_changes` time range, not project-scoped.**
   - Evidence: `internal/storage/file_churn.go:35-46` and `internal/storage/file_churn.go:109-114` query only `file_changes` by timestamp; no session/project join.
   - Impact: users with multiple repos in one DB see combined churn unless they narrow by date. This is not a blocker, but useful as release-note follow-up.
