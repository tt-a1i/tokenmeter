# TokenMeter v1.2.0 Release Notes (DRAFT)

> Not the final release post; for orchestrator/user review before publishing.

## 1-paragraph elevator pitch

TokenMeter v1.2.0 is the release where TokenMeter moves from "ccusage-compatible local reports" toward local observability for AI coding agents. It closes the largest v1.1 gaps with runtime LiteLLM pricing, Codex speed tiers, OpenCode SQLite, Droid sidecar metadata, responsive tables, token-limit block progress, project aliases, and unified config. It also adds features ccusage does not attempt: tool error pattern analysis, file churn heatmaps, anomaly webhooks, and an advanced search query DSL.

## What changed since v1.1

- `tm pricing refresh` can sync runtime pricing from LiteLLM and keep an offline fallback cache.
- Codex reports can price `auto`, `standard`, and `fast` speed tiers, including `~/.codex/config.toml` `service_tier` detection.
- OpenCode now reads modern SQLite stores such as `opencode.db` before falling back to older JSON layouts.
- Droid sessions can recover missing model names from sidecar JSONL logs.
- Daily, weekly, monthly, session, and blocks reports adapt better to narrow terminals with `--compact`.
- `tm blocks --token-limit` annotates 5-hour billing windows with progress and status.
- `tm daily --instances --project-aliases ...` normalizes multiple checkouts or worktrees into one project view.
- `tm config show/path/init` introduces the unified `~/.tokenmeter/config.json` entry point.
- `tm analyze --tool-errors` ranks failing tools, failure rates, and repeated error patterns.
- `tm analyze --file-churn` surfaces high-churn files from local activity.
- Webhooks can emit cost spike and usage regression anomaly events with cooldown controls.
- `tm search` now supports filters such as `tool:`, `session:`, `cost:`, `tokens:`, `since:`, `until:`, `status:`, and `platform:`.
- The new VitePress docs site under `docs/site/` documents sources, config, CLI reference, migration, and v1.2 changes.
- README and CLAUDE.md now describe the current CLI-first behavior instead of the removed v0.x Bubbletea TUI.

## Why this matters

v1.2 makes TokenMeter useful as a local operating dashboard, not only as a cost table. ccusage is excellent at batch token accounting; TokenMeter now layers in daemon-backed local data, Web Dashboard views, anomaly notifications, reliability reports, and searchable operational history. In real local data, `tm analyze --tool-errors --range all` exposed a WebFetch failure rate of 28.9%, which is exactly the kind of workflow signal that raw usage totals cannot show.

## Migration from v1.1

- Run `tm config init`, then inspect the result with `tm config show`.
- Move durable pricing and webhook settings from legacy JSON files into `~/.tokenmeter/config.json` when ready; legacy merge remains available.
- Review any `commands.<name>` overrides that explicitly set boolean fields to `false`; v1.2 treats explicit false as a real override.
- Seed the runtime pricing cache once with `tm pricing refresh` while online.
- Update release automation or scripts to use `tm daily --compact`, `tm blocks --token-limit`, and project alias flags only where the output shape change is expected.

## Known limitations for the release post

- `sources.<name>` config schema exists, but source-specific defaults are not applied yet.
- `session-length` remains a CLI flag and is not part of unified config defaults.
- Anomaly webhook cooldown is currently in-memory; daemon restart resets cooldown state.
- Tool error grouping depends on captured `result_summary`, so older local databases may have failures that cannot be grouped into patterns.
