## P1（v1.3 必做）

### P1-1: Search project scope filter

- Current state: `tm analyze --tool-errors` and `--file-churn` default to current project after `12e8d93`, but `tm search` remains whole-database by design.
- Recommendation: add `tm search --all-projects`, `--project NAME`, and `--project-aliases JSON|PATH`; include `project_scope` in JSON output for symmetry with analyze.
- Source: `.hive/v1.2-ship-checklist.md` Recommended Non-Blocking; `.hive/v1.2-final-acceptance.md` notes analyze scoping is now implemented; `docs/site/guide/search-query-dsl.md` documents filters but no project scope.

### P1-2: Canonical project identity for explicit project filters

- Current state: `tm analyze --project NAME` can match by full cwd or `filepath.Base(cwd)`, so same-basename checkouts can merge.
- Recommendation: introduce canonical project keys, or require aliases for ambiguous names and surface an error when ambiguity is detected.
- Source: `.hive/v1.2-final-acceptance.md` P2 finding on `--project NAME`; `12e8d93` scoped analyze implementation.

### P1-3: Persist anomaly webhook cooldown

- Current state: anomaly cooldown is in-memory; daemon restart resets cooldown state.
- Recommendation: persist cooldown state in SQLite or a small JSON state file, reload on daemon start, and test same-day/different-day behavior across restart.
- Source: CHANGELOG known limitations; `.hive/v1.2-release-notes-draft.md`; `.hive/v1.2-github-release.md`; `ae5f4bf` + `4c415ea` anomaly webhook work.

### P1-4: Improve tool error diagnostics when `result_summary` is empty

- Current state: tool error pattern grouping depends on failed tool calls having `result_summary`; old databases often have failures with empty summaries.
- Recommendation: render a specific diagnostic such as `no result summaries captured`, validate new collector failure payloads, and consider fallback grouping from params/status/session context.
- Source: `.hive/wave3-review.md` P2 finding; CHANGELOG known limitations; `.hive/v1.2-changelog-cross-validation.md` known limitations accuracy check.

### P1-5: Include generated shell completions in release archives

- Current state: GoReleaser archives include binary, LICENSE, README, README_EN, and CHANGELOG, but not generated completions.
- Recommendation: generate bash/zsh/fish completions during release packaging and add archive content checks.
- Source: `.hive/v1.2-prerelease-verify.md` GoReleaser final review; `.hive/v1.2-ship-checklist.md` Recommended Non-Blocking; `.hive/v1.2-goreleaser-dryrun.md` archive content list.

### P1-6: Fix docs/site Quickstart offline refresh command

- Status: closed before v1.2 ship.
- Resolution: mirror README: use `tm pricing refresh` in happy-path Quickstart, and move `--offline` to an offline behavior note with expected exit code.
- Source: `docs/site/index.md` Quickstart; `.hive/v1.2-pricing-e2e-verify.md` confirms `pricing refresh --offline` exits 1; `.hive/v1.2-final-acceptance.md` says README was fixed but does not cover this docs/site page.

### P1-7: Add release-check target

- Current state: release verification is manual across build, test, vet, race, e2e, help discovery, GoReleaser dry-run, and live pricing refresh.
- Recommendation: add `make release-check` or equivalent CI target to run build + `go test ./...` + `go vet ./...` + `go test -race ./...` + `make test-e2e` + selected help/discovery checks.
- Source: `.hive/v1.2-prerelease-verify.md` recommended action; `.hive/v1.2-ship-checklist.md` Recommended Non-Blocking.

## P2（v1.3 期望做）

### P2-1: Apply `sources.<name>` unified config

- Current state: schema exists but source-specific defaults are not applied.
- Recommendation: define source namespace precedence and apply `sources.<name>.defaults` / `sources.<name>.commands` to adapter commands.
- Source: CHANGELOG known limitations; `.hive/wave3-review.md`; `.hive/v1.2-changelog-cross-validation.md`; docs/site unified config scope.

### P2-2: Add `session-length` to unified config defaults

- Current state: `session-length` remains CLI-only.
- Recommendation: add `defaults.sessionLength` / `commands.<name>.sessionLength`, document naming, and cover CLI override precedence.
- Source: CHANGELOG known limitations; `.hive/v1.2-release-notes-draft.md`; `.hive/v1.2-github-release.md`.

### P2-3: Cache-aware `tm pricing refresh`

- Current state: `tm pricing refresh` always performs a network refresh unless `--offline` is set; report commands use cache-first `LoadRuntime`.
- Recommendation: decide whether `pricing refresh` should stay force-refresh or become cache-aware by default with `--force` for network refresh; document the chosen semantics.
- Source: `.hive/v1.2-pricing-e2e-verify.md` design clarification; CHANGELOG/README offline notes.

### P2-4: Document and test pricing TTL metadata

- Current state: cache TTL is controlled by JSON `fetchedAt`, not file mtime.
- Recommendation: update operational docs/checklists to simulate TTL by changing `fetchedAt`; add a small helper or test fixture if repeated in release verification.
- Source: `.hive/v1.2-pricing-e2e-verify.md` command notes.

### P2-5: Verbose diagnostics for OpenCode SQLite read failures

- Current state: SQLite open/query/scan errors are silently skipped so batch adapters can continue.
- Recommendation: add verbose/debug warnings, JSON diagnostics, or a per-source warning list while preserving resilient fallback behavior.
- Source: `.hive/wave2-review.md`; CHANGELOG known limitations; `.hive/v1.2-changelog-cross-validation.md`; `.hive/v1.2-ship-checklist.md`.

### P2-6: Droid sidecar fallback scan diagnostics or configurability

- Current state: Droid sidecar JSONL fallback scans only the first 500 lines as a large-log heuristic.
- Recommendation: document exact behavior near the source guide and consider a bounded configurable scan limit or warning when no model is found.
- Source: CHANGELOG known limitations; `.hive/v1.2-changelog-cross-validation.md`.

### P2-7: Weekly cross-year bucket consistency

- Current state: storage aggregation uses SQLite `%W`, while project-instance path uses Go `ISOWeek`; cross-year weeks can diverge.
- Recommendation: add cross-year tests and standardize on ISO weeks or document SQLite `%W` semantics.
- Source: `.hive/wave3-review.md` P2 finding.

### P2-8: VitePress build check in CI

- Current state: docs/site skeleton and guides exist, but VitePress build was not part of v1.2 acceptance.
- Recommendation: add docs build to CI or release-check after node dependency strategy is settled.
- Source: `.hive/wave2-review.md` P2 finding for `585b343`.

### P2-9: Centralize CLI help/shared flag metadata

- Current state: v1.2 repeatedly exposed drift between parsed shared flags and hand-written help/docs.
- Recommendation: generate command help from `cli.ParseShared` metadata or introduce a single shared flag registry consumed by parser, help, and docs tests.
- Source: `.hive/wave2-review.md` P2 finding; `.hive/wave3-review.md` cross-commit concern; follow-up fixes `5ef334f`, `bd28965`, and related help tests.

### P2-10: Make release behavior explicit in GoReleaser config

- Current state: release upload behavior relies on GoReleaser defaults and workflow gating.
- Recommendation: add an explicit `.goreleaser.yml` `release` section for draft/prerelease/name behavior if the team wants declarative release semantics.
- Source: `.hive/v1.2-prerelease-verify.md`; `.hive/v1.2-ship-checklist.md`.
